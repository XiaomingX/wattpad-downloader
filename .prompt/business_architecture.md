# 业务架构文档 (Business Architecture)

## 项目概述
Wattpad Downloader - 基于 Python + Chainlit 的 Wattpad 书籍下载工具，将在线内容转换为本地 TXT 文件结构。

## 核心业务能力

### 当前实现
- ✅ 支持 Story URL / Chapter URL / Story ID 多种输入方式
- ✅ 自动处理长章节分页内容聚合
- ✅ 结构化 TXT 存储（每章节独立文件）
- ✅ 元数据提取与封面下载
- ✅ 异步并发下载
- ✅ 代理支持（trust_env=True）
- ✅ 缓存机制（File/Redis 可选）

### 业务痛点与改进机会

#### [ ] 1. 用户认证功能缺失
**现状**: `cookies = None` 硬编码，无法下载付费/私密内容
**影响**: 无法访问需要登录的书籍
**方案**:
- 添加 Chainlit 登录界面集成
- 实现 `wp_get_cookies()` 调用流程
- 支持环境变量配置用户凭证

#### [ ] 2. 下载进度可视化不足
**现状**: 仅在 `cl.Step` 中更新文本进度
**影响**: 用户体验较差，无法感知实时进度
**方案**:
- 使用 `cl.Message` 配合进度条组件
- 添加章节下载速度统计
- 实现失败章节重试提示

#### [ ] 3. 批量下载能力缺失
**现状**: 每次只能下载单本书
**影响**: 效率低下
**方案**:
- 支持书单 URL 批量解析
- 实现队列管理系统
- 添加并发限制配置

#### [ ] 4. 输出格式单一
**现状**: 仅支持 TXT 格式
**影响**: 无法满足 EPUB/PDF 等格式需求
**方案**:
- 保留 TXT 作为默认格式
- 可选添加 EPUB 生成（依赖 `ebooklib` 已安装但未使用）
- 添加格式选择 UI

#### [x] 5. EPUB 模式已废弃
**现状**: README 提到"已从 EPUB 生成模式切换为 TXT 存储模式"
**影响**: `ebooklib` 依赖冗余
**方案**:
- 从 `pyproject.toml` 移除 `ebooklib>=0.18`
- 清理相关注释和文档

## 业务流程图

```
用户输入 URL/ID
    ↓
解析输入类型 (Story/Part)
    ↓
获取元数据 (API v3)
    ↓
创建书籍目录
    ↓
保存元数据 + 封面
    ↓
并发下载所有章节
    ↓  (每章节)
    ├─ 处理分页内容
    ├─ HTML → 纯文本清洗
    └─ 保存为 {序号}_{标题}.txt
    ↓
完成通知
```

## 数据模型

### Story (核心实体)
```python
{
    "id": str,
    "title": str,
    "user": {"username": str},
    "language": {"name": str},
    "description": str,
    "cover": str,
    "completed": bool,
    "mature": bool,
    "tags": List[str],
    "parts": List[Part],
    "isPaywalled": bool
}
```

### Part (章节实体)
```python
{
    "id": int,
    "title": str
}
```

## 待优化业务规则

### [ ] 6. 文件名冲突处理
**现状**: 使用简单的 `sanitize_filename()` 正则替换
**风险**: 不同章节标题清洗后可能重名
**方案**:
- 添加序号前缀保证唯一性（已部分实现）
- 检测重名并自动追加后缀

### [ ] 7. 错误恢复机制
**现状**: 单章节失败会导致整体下载中断
**影响**: 用户体验差
**方案**:
- 实现章节级别的错误捕获
- 记录失败章节列表
- 提供重试接口

### [ ] 8. 内容质量检测
**现状**: 无内容完整性校验
**风险**: 可能保存空白或损坏章节
**方案**:
- 添加最小字符数检测
- 检测 HTML 清洗后的异常模式
- 标记可疑章节供用户复查
